## 桌面固定回放

`e2e/t24-load-stage.spec.ts` 通过真实 Electron/IPC 和固定 HTTP 工具回放验证三条路径：

1. 建模后自动准备两工况条件阶段，卡片把均布力从全局改为局部、改数值、重力和负组合系数；编辑中暂停预览并禁用确认。一次确认原子应用并自动计算 CB1，回执与冻结原始工况荷载、系数一致。整组撤销/重做、保存重开保留正式身份和真实结果。
2. 自然语言只更新重力，原均布力及组合保留；从方案移除仍被荷载和组合引用的新工况，具体缺失引用阻止确认。拒绝后正式荷载与结果不变。
3. 从支座阶段直接用卡片创建新工况、均布力、自重、用户组合及零系数。确认只应用条件，未请求计算时不自动求解。

固定工具输入、输出、明确卡片修改以及本地结果见 [T24-replay.json](T24-replay.json)。组合结果对话回执明确外部 CB 身份及全部原始工况来源，不把内部有效荷载容器 LC1 当作组合来源。

## 自重标记与双主题

## 真实 DeepSeek

`node scripts/verify-t24-online.cjs` 使用用户既有的本机加密凭据临时隔离副本，不输出密钥、不更改正式连接。真实 `deepseek-flash` 流程通过：两层 12 节点/16 杆件；第一次确认几何后 AI 读取正式节点、杆件及资源，准备底层四个六自由度支座；LC1 改名恒载并计入 g=(0,0,-9.81) m/s² 自重；新活载工况仅在顶层 (0,0,6)→(6,0,6) m 的梁上施加全局 q=(0,0,-2) kN/m；用户组合系数恒载1、活载0.5。第二次确认自动本地求解该组合，无重复计算授权。

确认前保存只有几何和原默认工况，没有正式支座、荷载、组合或分析结果。确认后工况映射、加载杆件坐标、荷载归属和冻结组合输入逐项核对通过。自重标记及组合回执完善后再次真实调用通过。五条桌面对话记录包括两次联网、两次本地确认和一次本地求解。

真实输入输出和完整实际结果见 [T24-online.json](T24-online.json)，桌面见 [T24-online.png](T24-online.png)。`npm run evidence:t24:online` 可重验，会产生 DeepSeek API 用量。
