# T32：典型规模性能验收与修正

## 结论与复现

固定 Windows 机器、生产构建和三个模型的 9 次独立桌面运行均通过测量前登记的指标。范围为 58、399、1,120 根杆件；结果不构成其他硬件、更大模型或全部杆件矩阵附录的性能承诺。

- 标准：[ADR-0033](../decisions/0033-t32-performance-contract.md)，基线提交 `663bea8830685b12f8e38a795cfab21321b91d8a`，阈值未放宽。
- 原始正式记录：[T32-final-results.json](T32-final-results.json)，包括每次耗时、回调/帧间隔、全部内存采样、输入及构建 SHA-256、输出字节数；`passed: true`，9 轮无失败。
- 复跑：`npm run evidence:t32`。默认三个规模各 3 次，隔离用户目录，实际 Electron 界面、Worker 和本地文件写入。`T32_MODEL`、`T32_REPETITIONS`、`T32_LABEL` 仅用于诊断；正式验收保留默认范围和重复次数。
- 固定模型入口：`src/validation/performance-models.ts`；已保存 [S](T32-S.framemind)、[M](T32-M.framemind)、[L](T32-L.framemind) 两次历史结果项目，以及相同规模的 Word/PDF 和最终界面截图。

本机 Windows 11 家庭版中文版 10.0.26200；i7-14650HX，16 核/24 逻辑处理器；16,873,545,728 bytes 物理内存。Node 24.19.0、Electron 44.5.1、Chromium 152.0.7977.130；内容窗口 1440 × 900，离线生产构建。提交字段指测量时的基础 HEAD；未提交工作树的实际构建由原始记录的哈希定位。ADR 文件哈希是正式测量开始时版本，后续仅补充审查和实现说明。

| --- | --- | --- | --- | --- | --- | --- |
| S | 36 / 58 | 12 | 36 / 34 | 216 | 2 | 607,238 |
| M | 196 / 399 | 49 | 196 / 252 | 1,176 | 2 | 3,980,160 |

跨长、层高、材料、截面、支座六自由度、集中荷载、均布荷载、自重和 CB1 系数均按 ADR 固定。报告正文包含全部节点/杆件结果；附录选择 M1 杆件过程、全部自由度编号及约束/荷载向量，沿用 72 阶大矩阵上限。

## 正式耗时

下表单位 ms，每格为「3 次中位数 / 最大值」。逐次均通过，未以均值替代失败判定。打开包含树、三维计数及两帧等待；旋转为实际鼠标拖动和相机变化断言；选取为稳定对象的树入口及属性显示。求解包含快照、Worker 通信、结果提交和期间旋转。取消在真实 Worker 的取消按钮出现时立即点击，并验证取消后仍是两次历史结果、下一次完整求解后为三次。批量提交修改 20 杆截面转角后撤销。

## 失败、瓶颈及修正

完整保留 [baseline](T32-baseline-results.json) 和 iteration1—iteration9 原始记录，不能将诊断迭代算作正式验收。早期测量还存在属性标签选错、短任务在自动化点击取消之前完成，以及全页面可访问名称计算污染；这些失败保留，修正测量方式后的结果另行记录。

| 阶段 | 观察 | 修正及边界 |
| --- | --- | --- |
| baseline | M 打开约 7.09 s，L 未完成打开且采样工作集 2.68 GiB；后续步骤因选择器失败未完成 | 树/结果分页，过程折叠按需构建；不宣称基线完整通过 |
| iteration3 | L PDF 失败 `ERR_INVALID_URL`；同步报告和大量对象导致回调停顿 | 临时离线 HTML 替代超长 data URL；报告验证、内容和打包迁入 Worker |
| iteration4—7 | 大量条件文字/绘制对象、重复结果扫描、每次项目序列化使大模型持续超时；早期自动化名称扫描亦污染数值 | 合并显示几何，保留稳定命中对象；密集条件只标注所选编号；缓存采样及有效性；保存检查点比较 |
| iteration8 | L 内存 3.24 GiB，LC1 切换 1,008.6 ms；其他操作逐渐达到阈值 | Word 原生表格直接序列化，PDF 以有限表格批次排版，完整数据保留 |
| iteration9 | L 内存降至 1.82 GiB；LC1 切换 1,023.5 ms 仍失败 | 去除输入未变时的整项目编码和重复来源校验，再进行正式 9 次运行 |

帧率审查指出原采样包含拖动前后自动化区间，正式记录已改用真实 pointerdown/up 边界。模型、阈值和操作未调整。早期数据受不同工作树、调试和自动化干扰，不作为精确加速比例；最终构建独立完成所有重复验收。

## 回归、版面与审查

`npm run check` 已通过：两套 TypeScript 检查、38 个文件的 272 项单元测试、生产构建和全部 73 项真实 Electron 桌面测试（4.8 分钟）。覆盖保存重开、异步保存检查点、撤销/重做、Worker 取消及迟到结果、三维选择/相机、组合与报告冻结来源；新增分页测试能访问最后的 N36/M58 和真实矩阵，关闭时不构建矩阵表格。

`npm run evidence:t31` 复跑通过，另存 [T32-numerical-results.json](T32-numerical-results.json)：22 个有效算例、7 个无效/不稳定模型、2,322 项检查、零失败，容差沿用 ADR-0032。最大绝对误差 m `1.284e-16`、rad `4.770e-17`、kN `4.547e-13`、kN·m `1.535e-12`；未修改求解实现版本或阈值。新增均布悬臂内力采样以独立解析参考验证中间站点，避免只与相同实现互相比对。

`scripts/verify-t32-layout.py` 在隔离、只读 Word 实例中打开三份计算书并导出检查用 PDF，以 documents 的 `render_docx.py` 光栅化全部页面。产品 PDF 分别为 43 / 211 / 544 页，原生 Word 排版为 56 / 285 / 746 页，共 1,885 页；全部页面的文本边界均在纸张内，Word XML 中的每个正文/表格段落均在两种渲染文本中找到，PDF 全局页码全部正确，中文字体嵌入。见 [T32-layout-results.json](T32-layout-results.json)。核验脚本排除页脚后再跨页连接 Word 文本，修正分页段落的假缺失；未改动报告正文。完整页面缩略图已检查，首/中/末页另作全尺寸核对，样本见 [大模型 PDF 首面](T32-L-pdf-first.png)、[末面](T32-L-pdf-last.png)、[Word 结果表](T32-L-word-middle.png)、[Word 末面](T32-L-word-last.png)。没有内容遗漏、越界、缺字或覆盖。

开发版面核验需要本机 Word、Python/PyMuPDF/Pillow/pywin32 和 Poppler；它们不参与产品导出，也不计入上述应用生成耗时。完整复核命令为 `python scripts/verify-t32-layout.py --renderer <documents/render_docx.py>`；`--reuse-rendered` 仅对本次已有渲染输出重跑内容/边界检查。

Standards / Spec 两轴审查均发现可预测 Word 表格占位符会覆盖同名项目标题，已改为碰撞检查的 UUID 标记、终止边界和恰好一次替换检查；公开导出测试先复现失败，再确认标题、所有表格末行和图形保留。Spec 另发现帧率采样区间问题，已修正并经只读复审确认。两轴均无剩余阻塞发现。

已知限制：仅本机及固定模型；批量修改为 20 杆；报告选首杆过程而非全部 1,120 杆矩阵；密集场景标注策略在界面有说明；大模型 PDF 分批会重复表头并增加排版耗时。矩阵求解仍为密集部分主元方法，未承诺更大规模，也未覆盖 T33 首次使用或 T34 安装发布验收。
