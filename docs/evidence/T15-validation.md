# T15 验收记录：新旧结果来源与前后对比

## 实现决策

结果以一次求解的稳定 `analysisId` 追加保存，同一工况或组合的再次求解不会覆盖旧结果。每份结果继续保存完整冻结输入；当前模型通过输入快照比对标记结果为“当前”或“已过期”。对比入口要求用户明确选择两份结果，按项目、来源、单位、自由度顺序和稳定对象 ID 检查兼容性。

## 自动化核对

- `src/domain/analysis-comparison.test.ts` 验证同一来源的两次运行、截面参数变化、节点位移/反力差值、杆端内力差值、两份结果保存重开，以及不同来源的明确不兼容提示。
- `npm run typecheck` 通过。
- `npm test -- --run`：20 个测试文件、111 项测试通过。
- `npm run build` 通过。
- `e2e/t15-analysis-comparison.spec.ts` 通过真实 Electron 流程：首次分析、修改截面、再次分析、打开前后对比，并核对模型变化、节点响应和杆件内力表。
- `e2e/t11-load-cases.spec.ts` 回归验证多工况保存重开；同一工况复核后文件中保留 3 份分析结果，活动工况仍读取最新结果。

## 交互验收路径

1. 完成一个工况的分析；结果输入区显示来源工况、冻结模型版本、当前/已过期状态和历史结果数量。
2. 修改节点、杆件、材料或截面后，旧结果仍可查看但明确标记为“已过期”；旧图表不被当前模型的新参数冒充。
3. 重新运行后点击“前后结果对比”，选择两份结果；面板显示各自来源和模型版本。
4. 兼容结果显示模型参数变化、节点位移与支座反力差值、杆件局部轴起终点六分量内力差值；每行可按稳定 ID 定位当前对象。
5. 不同来源、单位或无法匹配对象时显示具体原因，不展示误导性的数值差值。
6. 保存并重开项目后，历史结果及其冻结输入仍可用于同样的选择与复核；撤销编辑恢复项目快照，不改写历史结果来源。

## 已知边界

对比只使用同一项目中稳定 ID 可匹配的节点和杆件；不同项目或不兼容来源不能合并比较。结果历史目前随项目文件持久化，不包含会话撤销栈。
