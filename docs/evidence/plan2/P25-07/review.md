## Standards

初审发现：

修复：恢复操作先校验日志、旧内容哈希、索引身份及可达 Git 快照；无法确认 Git 状态时保留日志与文件。托管项目打开时要求有效保存索引，并验证 schema、项目身份、历史身份、commit 和内容哈希。增加损坏日志、缺失 Git、索引不符和索引缺失的真实存储测试。恢复预览与实际应用共用归一化函数。

复查结论：两项原有发现已解决；没有新增规范违例或可执行的代码异味发现。审查 agent 检查代码和测试，测试由主 agent 执行。

## Spec

需求来源：`PLAN2.5.md` P25-07、`PRD2.5.md` 第 10 节与 ADR-0078。

初审发现：

- P1：另存为后磁盘 taskState 和同 projectId 的会话缓存可重新激活旧可执行草稿。
- P1：保存锁期间完成的分析结果可能被项目激活守卫丢弃。
- P2：Git update-ref 报错或超时后，引用可能已经发布；直接回滚文件会形成不一致。

修复：另存为前清除可执行任务状态，取消旧运行任务，移除按 projectId 回用可执行会话的缓存。保存与分析相互阻止进入，覆盖已运行分析与保存期间发起分析两种顺序。引用发布异常后读取真实 main，按已发布、未发布和无法确定分别完成提交、回滚或保留恢复日志。

复查结论：旧任务隔离、保存与分析竞态、Git 发布异常的一致性恢复三项发现均已解决；只读复查未发现具体回归问题。

桌面回归补充发现：另存为后的聊天面板回写空任务状态，导致刚保存的项目误判为未保存。已忽略不存在 taskState 时的全空回写，并按会话身份拒绝同 projectId 的旧回调；原桌面用例覆盖连续另存为与打开。Spec agent 再次确认：有效任务与已有状态的清空仍保存，旧会话不会恢复执行状态。
