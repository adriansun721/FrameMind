# T2-10 一致的自动恢复快照

日期：2026-10-05（Asia/Taipei）。环境：本机 Windows、仓库锁定的 Node／Electron／React 依赖。桌面 Agent 使用固定工具回放，不计为真实 AI 联测。

## 已交付

- 独立本机自动快照含同版本模型、任务、冻结计算输入与回执；不覆盖正式项目。250 ms 捕获窗口、2 秒检查／失败重试、跨项目切换捕获、每项目三代、临时文件忽略和损坏回退见 [ADR-0043](../../../decisions/0043-consistent-automatic-recovery-snapshots.md)。
- 启动先列恢复来源，用户选择前不挂载工作台。新项目显示尚未手动保存；已有工程显示正式保存路径／时间与独立快照时间。恢复工程继续标为未保存，正式保存后清除来源标记。
- 草案保持待确认，暂停／失败状态保留，恢复不自动启动 AI、深度探索、正式修改或计算。确认模型与回执作为同一不可变工程对象进入快照，重启重复确认和撤销后重试沿用持久账本。
- 中文路径可用，写入失败保留旧快照并提示手动保存／自动重试。SHA-256 覆盖载荷及来源，损坏快照跳过并提示较早完整代际；凭据在项目和快照中脱敏。

最终验证：

- `npm run build` 通过，包含前后端 TypeScript 检查及 Electron／Vite 产物构建。
- `npm test -- --maxWorkers=4`：完整运行 51 个文件、373 项测试，全部通过（22.46 秒）。仅限制并发，保留原用例超时与数值判据。恢复存储专项为 12 项。
- `node scripts/run-e2e-isolated.cjs e2e/plan2-t2-10-recovery.spec.ts e2e/plan2-t2-09-restart.spec.ts e2e/plan2-t2-05-coordination.spec.ts e2e/t06-analysis-task.spec.ts e2e/t27-ai-recovery.spec.ts`：29 项全部通过（2.2 分钟），其中 T2-10 为 11 项。
- [Standards 与 Spec 独立审查](review.md)发现的问题均已修复并通过复审。恢复入口双主题截图已人工查看。

测试调整：旧正式项目重开场景现在显式选择“暂不恢复”，不跳过恢复功能的真实用户选择；新增故障测试在启动 DOM 可用后才检查恢复候选，避免把 Chromium 创建窗口时的空白页面当作恢复界面。曾有一次主进程直接终止留下 Chromium 子进程锁文件，故障测试改为强制结束完整 Electron 进程树；最终运行没有放宽工程内容、回执一致性或数值断言。

截图：[启动损坏回退（深色）](startup-fallback-dark.png)、[启动损坏回退（浅色）](startup-fallback-light.png)、[恢复后的回执（深色）](recovered-receipt-dark.png)。已人工查看双主题恢复入口，来源文字、路径换行与选择按钮可见。截图仅辅助核查来源和交互，模型／回执正确性通过公开工程内容断言。

确认事务故障测试使用 CDP 调试暂停，保留真实事务与序列化行为：提交按钮捕获阶段对应模型提交前；生成 12 节点工程内容的序列化发生在模型生成后、回执组装前；带一条回执的完整工程序列化对应回执生成后、快照捕获前。各暂停点强制结束全部 Electron 进程，再恢复先前未确认草案并确认一次，核对 12 节点与唯一回执。快照原子改名后的中断另核对已应用模型与回执同时恢复。没有模拟独立的“模型磁盘写入”和“回执磁盘写入”，因为正式实现把两者写入同一代际。

## 验证边界

恢复的是最近成功提交的完整快照，不保证捕获窗口内或磁盘故障期间的新工作。验证进程异常终止，不替代掉电／硬件损坏测试、真实 AI 联测（T2-11／T2-41）或干净 Windows 安装（T2-44）。
