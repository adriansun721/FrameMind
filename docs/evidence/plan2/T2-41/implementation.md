# T2-41 实现记录

日期：2026-10-07（Asia/Taipei）。依据 PLAN2.0.md T2-41、PRD2.0.md US2-001—033、077，AC2-01—11、20。

`propose_task.edits={operations,source,sources?}` 复用严格工具解析和 `applyProjectEdits`。几何、材料、截面、连接分割、节点合并、质量、释放、阻尼、分析工况及输入谱可与框架、条件和分析意图一次确认。`sources` 与操作等长，用于区分同一任务的用户值、目录值、建议和假设；不同来源字段拆成独立操作。未知来源不能确认。

材料新增、修改、复制、删除及条件/工况删除进入共享领域入口。目录材料保留目录身份与来源；工况删除与手动操作一样级联清理关联荷载、组合和分析工况，保留冻结历史结果。资源被引用时仍遵守共享入口的保护规则。预览展示全部差异及连接、合并、截面影响。

新框架对象使用明确的草案身份，确认时映射正式身份。预览预留框架占用的各类编号，再处理创建、复制和分割。确认核对映射后的真实差异、新建身份和关联杆件，回执包含实际正式身份及最终读回；整体任务只递增一次修订并支持整组撤销。重复确认和项目重启不重复执行。手动删除草案目标进入冲突提示。

Agent 快照和本地任务基础只保存工程输入，避免递归嵌套旧任务历史；恢复合并继续使用完整项目以保留确认回执。结果读取保留冻结分析记录。长回复保留 Unicode 与引用 token，最多分 16 批显示，避免逐字更新反复持久化大结果快照。

固定协议在运行前落盘。版本 2 首轮真实联测失败保留；版本 3 增加屈曲确认后的实际原生求解与新结果引用，以及二阶失败后的用户指定修复求解，未放宽原门槛。版本 3 回放又发现旧恢复测试仍拦截 Worker、待恢复输入未包含实际原生求解器与网格。现在持久化和执行统一准备同一输入；故障注入阻塞原生 IPC，重启后恢复真实原生处理器，仍严格比较完整输入。版本 4 增加对应契约及原 T2-11 回归，并核对运行期间源码、构建及原生核心哈希没有变化。

每类两次，七类共 14 个 Agent 样本；协议回放还覆盖原协调、重启和恢复桌面流程。

版本 4 扩展的原 T2-11 回归发现两个仍要求已退役 `/2` 核心的断言；对应数值、确认、隔离和幂等检查已通过。版本 5 明确要求输入及运行记录都使用当前生产 mesh-static `/4`，原数值容差保持不变，同时保留全部样本、重复和检查门槛。诊断期间改变源码/构建的旧轮次不能作为最终冻结版本验收。

- `npm run evidence:plan2:t241`：构建并运行两次契约测试及固定响应的实际 Electron 流程。
- `npm run evidence:plan2:t241:online`：同一固定样本调用实际 DeepSeek HTTPS，使用既有加密连接，不替换传输。
