## 公开入口与独立数值参考

沿用 ADR-0008、ADR-0022、ADR-0023 的公开模型、工具、历史与 Electron 入口。新增条件测试在公开工具及阶段确认后求解：4 m 悬臂，E=200 GPa，A=0.01 m²，Iy=0.0002 m⁴，Iz=0.0001 m⁴，端力 (8,5,-3) kN、端矩 (2,1.5,-1.25) kN·m。独立闭式参考：端位移 (0.000016, 0.004833333333333333, -0.0019) m，固定端反力 (-8,-5,3) kN，My=-13.5、Mz=-18.75 kN·m。

测试覆盖：预览不改变正式模型且不可求解；来源、单位及六分量；缺失与空列表；未知字段、脚本、非有限/非数字分量、错误节点与工况；冻结内容、基础项目和版本；单修订号、保存往返；整组撤销重做、幂等（包括撤销后）；已有条件更新需新确认且保持身份。故障注入在支座命令成功后的荷载编号上限失败，整个事务及编号回滚。

## 桌面流程

`e2e/t23-analysis-conditions.spec.ts` 通过真实 Electron/IPC 与固定 HTTP 回放验证：

1. 用户请求建模并计算，一次建模确认后自动准备四支座/一荷载阶段。逐项核查约束及力/力矩，编辑 FX 后确认按钮禁用且预览暂停；更新确认后自动求解，并展示结果。后续荷载更新再次预览确认，产生独立实际结果；撤销恢复完整旧荷载。
2. 手动编辑使条件卡片失效；刷新后确认。模型检查失败和约束不足的方程求解失败在对话显示，正式模型保留。
3. 挂起 Worker，在对话取消本地分析；已确认支座、荷载保留且无虚假结果。继续本地计算、再次取消及拒绝后续条件均不重复应用模型。
4. 网络请求在途时撤销计算意图，迟到工具回复不能启动求解；未请求计算时 AI 自行请求工具、纯文字回复都不能绕过本地请求和确认边界。
5. 既有 LC1/LC2 的非当前工况荷载及计算来源一起预览确认，不能误算旧工况；自然语言“不计算”撤销前一次请求，确认只应用条件。“请对当前模型进行分析”经空变更阶段确认后继续已确认 LC2 计算。

首次专项发现条件图例遗漏显示分支，已修复产品图例；另一项失败是自动显示变形图使原生 `<output>` 也具有 status 角色，保存辅助改为定位真实 footer 状态栏，保留产品的语义。工况专项的全套运行还暴露原保存辅助仅检查旧状态提示、可能在新原子保存完成前读到旧文件，已增加等待公开“未保存修改”标记消失，没有放宽业务断言。修复后补充在途撤销、自然语言及工况绑定验证并进行最终复验。

### Standards

### Spec

初审发现普通“不计算”和“计算先取消”未撤销之前的请求，以及常见“并进行计算”“对当前模型进行分析”等表达不能续算。已修复并补充单元/桌面验证。复审又发现裸“不”的匹配误伤“不同节点”“不改变荷载，继续计算”，以及“请分析当前模型”“继续分析”未识别；已约束否定语法并补齐模型分析表达。最终独立复审直接执行最新函数核对所有例句，无新需求缺口；Spec 未解决发现 0。

边界：AI 支持当前节点支座与集中力/力矩阶段；不配置均布荷载、自重或工况组合，不解释规范符合性。会话请求与回执不随项目保存，后续恢复范围由 T27 定义。
