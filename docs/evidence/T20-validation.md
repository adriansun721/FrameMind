## 真实 Electron 回放

`e2e/t20-readonly-ai.spec.ts` 使用两个节点 (0,0,0)/(4,0,0) m、默认 Q355 材料/箱形截面及一根 M1 杆件：

1. 通过设置保存假凭据，从数据表定位 M1；对话上下文显示 `member_0001`。
2. 转角草稿改为 45° 但不提交，工具读取仍为 0°，输出端点 x=4 m。
3. 保存转角后，三维显示 45°，下一次 `read_objects` 输出也为 45°。
4. 保存 `.framemind`，真实文件中转角为 45°，不包含 Key 或对话文字。
5. 深/浅两主题、1440/1080 宽度下检查无页面横向溢出，输入区保持面板内，WebGL 有实际内容，并截图核验。
6. 已回复的 R6 撤销到 R5，再编辑为内容不同的 R6：旧回复显示历史版本。先用此操作重现旧实现没有标记的失败，再修复模型身份判断并通过（5.5 秒）。

`e2e/t20-ai-boundaries.spec.ts` 验证无凭据时可打开设置恢复、脚本失败、修改等待确认且保存模型未改变；混合选择两个节点和一根杆件时工具对象 ID 与选择完全一致；主动取消、切换选择、提交模型修改、移除凭据后，故意迟到的网络回复不进入界面，已提交节点坐标仍保留。

`e2e/ui05-panel-layout.spec.ts` 继续验证收起/展开 AI 面板保留输入草稿、模型选择及原有画布，发送入口已更新为可用。

一次专项运行的首项在 `app.close()` 阶段超过 30 秒：业务断言和工程文件核对均已完成；单独重跑该项通过（4.0 秒）。首次完整桌面回归 37 项通过、4 项启动失败，发生时同时打开的应用与部分旧测试共用默认 userData。最终改用独立临时 `FRAMEMIND_E2E_USER_DATA_PATH`，原来四项启动失败均通过：全套 40 项通过、T20 只读场景一项在设置保存按钮交互超时；随后重跑全部 T20 与 UI05，6 项全部通过（24.6 秒，其中只读场景 4.4 秒）。保留原有断言和超时，没有为通过放宽条件。最终 41 项桌面行为均取得通过记录，但本次仍观察到 Electron 自动化的偶发启动/交互/退出超时，不声称一次全套零失败。

## 真实在线补验（已通过）

用户初次选择先完成离线验收，随后在应用中保存自己的 Key 并授权补验。2026-10-02 使用 `deepseek-flash`、真实官方 HTTPS 网络，通过生产主进程与桌面桥执行连接测试和三次工具问答。最终验收没有替换 fetch 或返回固定网络样本。

输入为 N1=(1.25,-2,3.5) m、N2=(5.25,-2,3.5) m、Q355 材料 E=206 GPa、箱形截面 A=0.01 m² 和 M1。具体证据：[原始工具输入/输出与完整真实回复](T20-online.json)、[真实对话截图](T20-online.png)。

- R5 选择 N1：真实 `read_selection` 和 `read_objects` 返回 `node_0001` 及已知坐标，回复的 ID、三坐标和 m 单位一致。
- R5 选择 M1：真实工具及回复中的端点 ID、长度 4 m、转角 0°、E=206 GPa、A=0.01 m² 与正式模型相同。
- 手动提交 M1 转角 45°，模型变为 R6：三维、属性和数据表均显示 45°；重新读取返回长度 4 m、转角 45°，真实回复使用本次值，R5 回复标记历史版本。
- 连接测试返回 `success`；三次问答共五条已完成工具记录（2、1、2 条）。逐条核对真实回复，未发现编造模型数值或模型变更。

首次真实工具请求返回 HTTP 200，但工具调用附带 `index`，此前白名单误判为非法响应。增加保留该字段的固定响应测试，先证实旧实现失败，再仅兼容响应中的合法索引并剥离；测试同时证明入站 IPC 仍拒绝未定义字段。修复后真实工具循环及三次问答通过。负坐标回复可能使用 Unicode 减号，验收只统一减号字形，不改变数值。

可复验命令：`npm run evidence:t20:online`（会产生实际 DeepSeek 用量）。脚本将应用的加密凭据及 `Local State` 复制到临时用户目录，在进程初始化前恢复其加密配置；脚本不解密、不输出或提交这些文件，也不修改用户实际工程或凭据。关闭应用及验收失败时仍通过嵌套 finally 执行清理，删除前检查绝对路径在系统临时目录及专用目录前缀内。

追加回归：`electron/deepseek-chat.test.ts` 29 项通过；`npm test` 182 项通过；`npm run build` 包含类型检查并通过；T19/T20 的六项真实 Electron 固定回放均通过（25.1 秒）。两路复审确认需求已满足；规范审查指出的关闭失败跳过临时副本清理问题已通过嵌套 finally 修复。本次未为这项传输兼容修复重复运行无关的完整桌面套件，原 41 项覆盖及偶发超时记录仍见上文。

## 2026-10-03 时间线状态复验

本次生产构建（包含类型检查）通过，完整单元测试 41 个文件、285 项通过，新增桌面回归 1 项通过。复验基于 `1b5d60c` 后的时间线修复；没有重复调用真实 DeepSeek，原在线验收见上节，也没有把当前全部桌面套件标为重新通过。
