## 公开工具与桌面流程

`src/workspace/ai-proposal.test.ts` 通过 T20 公开工具和任务入口验证：仅层数的已知/缺失卡片、用户/建议来源、两层网格独立几何参考、正式分析输入不变、参数冲突与明确改正、卡片编辑优先、无效尺寸/资源/脚本、层数与层高项数冲突、过大预览保护和自然语言拒绝。参考几何为一跨 X=6 m、Y=4 m、两层各 3 m：地面与两层共 12 节点；8 柱、每层 4 梁，共 16 杆件；最高角点 (6,4,6) m。

初次专项公开入口 45 项通过；复审补充来源保护和终止拒绝的回归后，完整单元测试 27 文件/189 项通过。类型检查和生产构建通过；构建沿用既有主资源超过 500 kB 的提示，不计为 T32 规模性能验收。

`e2e/t21-frame-proposal.spec.ts` 经真实 Electron/IPC 和固定 DeepSeek HTTP 回放验证三条流程：

1. 仅描述两层，卡片保留层数已知与其余缺失；自然语言补齐后产生批量预览。卡片改 X 跨到 8 m 后，涉及对象中最高角点为 (8,4,6) m；可重新生成和拒绝。整个过程保存的正式项目与之前一致，拒绝后继续手动创建节点。
2. X=6 / X=8 冲突明确显示、暂停几何；负跨长被拦截；直接编辑解决冲突；自然语言改第二层为 4 m 后保留卡片 X=8；自然语言拒绝清除方案。
3. 已计算单杆悬臂保持有效输入和结果；预览期间保存一致，再计算仍只使用单杆正式输入。正式变化使方案失效；只读摘要不能重新激活；重新生成后可核对当前模型。拒绝在途更新后，迟到的建模响应不能恢复预览。

T20 + T21 专项桌面回归共 7 项通过。初次完整桌面套件 39/44 通过，5 项在默认用户目录下首次界面检查失败；保持断言和超时不变，用隔离用户目录复跑相关 6 项全部通过（23.2 秒）。已将 `npm run test:e2e` 接入临时用户目录 runner，避免与正在运行的桌面实例争用配置。

最终完整隔离套件 43/44 通过（2.6 分钟）；剩余 T21 第一项在重复保存的原子文件替换间隙读取到 `ENOENT`。旧“已保存”反馈不能说明这次替换已结束；测试读取改为仅在短暂文件不存在时重试，完整模型/结果相等断言保留。随后 T21 三项均通过（12.7 秒），44 项桌面行为均有通过记录。未声称最后一次完整套件零失败。

## 真实 DeepSeek

使用用户此前配置的本机加密凭据，临时隔离配置副本；脚本不解密/输出 Key，不修改正式连接设置，结束后清理副本。没有 HTTP 回放或 fetch 替换。

`node scripts/verify-t21-online.cjs` 使用真实 `deepseek-flash` 通过四轮：

1. “建立一个两层空间钢刚架。先整理已知与缺失参数。”调用 `propose_frame`，层数 2 来自用户，其余保持缺失。
2. 自然语言补齐两向跨长、层高、原点、钢材和梁柱截面，生成 12 节点/16 杆件预览。
3. 用户卡片把 X 跨改为 8 m 后，自然语言改第二层到 4 m，工具保留 X=8，层高变为 [3,4]。
4. 自然语言拒绝调用 `discard_frame_proposal`，清除三维方案；最终正式项目保存文本与初始保存完全相同。

完整实际工具输入/输出见 [T21-online.json](T21-online.json)，画面见 [T21-online.png](T21-online.png)。第一轮诊断经历一次界面尚未就绪，以及两次空选择读取；已加入界面就绪等待并修正新建请求规则，再次四轮通过。拒绝终止逻辑修复后再次四轮真实联测全部通过，最新记录已更新；未把失败尝试记录为通过，模型响应仍受本地工具校验约束。
