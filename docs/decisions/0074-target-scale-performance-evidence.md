# ADR-0074：目标规模性能与资源证据

日期：2026-10-07（Asia/Taipei）。范围：PLAN2.0 T2-42；US2-050、054、083、084；AC2-22。

正式测量分为两个命令：`npm run evidence:plan2:t242:register` 构建并事先登记，`npm run evidence:plan2:t242` 核对登记后运行。`node scripts/summarize-plan2-t242.mjs` 生成可读汇总。登记文件使用独占创建，已有版本不覆盖；改变源码、构建、机器环境或预算必须保留旧轮次并发布新协议版本。正式运行前后核对源文件、锁文件、构建和原生可执行文件哈希。测量失败返回非零，不改变门槛，不读取旧小模型结果补齐。

模型固定为九层空间钢刚架，5 m 跨、3 m 层高，基底六自由度固定，真实 RHS 200×400×10 mm 截面，E=200 GPa、ν=0.3、ρ=7850 kg/m³。目标模型 10×10×10 个节点，1,000 工程节点、3,000 工程杆件，包含 900 柱、1,620 正交梁和各层分布的 480 水平斜杆。较大模型 12×12×10 个节点，1,440 工程节点、4,392 工程杆件。没有为了压低方程数固定上部结构。分别为 6,000／8,640 实际自由度，600／864 基底约束，初始 5,400／7,776 方程。

LC1 为顶层每节点 (1,0.5,-10) kN，LC2 为每非基底节点 -10 kN、正交梁全局 -2 kN/m 和真实自重。静力与二阶使用 LC1；屈曲明确 LC2 固定、LC1 参考；模态使用结构质量；随机计划绑定同模型最新六阶模态、用户来源 2% 阻尼、0–25 Hz 单边白噪声节点力谱 1 kN²/Hz、末节点全局 X 激励与 X 响应，65 初始／20,001 最大频点。依赖不足时实际计算规模、频点和峰值为缺失，不伪造模态或结果。

全部分析事先明确候选每杆 1／2 单元。静力方程预算 12,000，高级方法 1,200，均沿用产品合法运行配置。目标二级网格需要 4,000 计算节点、6,000 单元、23,400 方程；较大模型需要 5,832 节点、8,784 单元、34,128 方程。预算不足拒绝分支与实际可完成分支分开记录；静力初始网格结果若标为 `budget-exhausted`，不能宣称已收敛。现有高级方程配置不足以支撑目标规模，因此测量工具交付不等于 AC2-22 通过。

v1 门槛在正式运行前固定于 [t242-protocol.json](../../src/validation/t242-protocol.json)：模型领域构造、打开、保存、重开分别 5 s；旋转、选取、提交 1 s；结果切换 2 s；静力 30 s；二阶、屈曲、模态、随机各 60 s；取消 500 ms；资源失败反馈 5 s；Word／PDF 各 60 s；主线程回调间隙 500 ms、旋转帧 P95 100 ms／单帧最大 500 ms。Electron 采样工作集总和 2 GiB，原生峰值提交内存 512 MiB；原生超时沿用 120 s。较大模型使用同一门槛，可以失败，不在产品引入节点／杆件数量上限。v2 只修复测试进程隔离，所有门槛、模型与三次重复保持相同。

v1 正式采集中，Windows Playwright 的 `app.process()` 实际返回启动 shell，超时标记已记录但终止没有结束真实 Electron 主进程。保留 [v1 登记](../evidence/plan2/T2-42/registration-v1.json) 与 [中止轮次](../evidence/plan2/T2-42/runs/2026-10-07T13-09-55.166Z/results.json)，不当作有效完整截止证据。中止前源码／构建匹配；外部核实专属配置后结束真实测试树并确认无 Electron／core 遗留。v2 缓存实际主进程 PID，300 秒整轮截止执行 `taskkill /T /F`，从外部核实实际主进程及已观察的原生 PID 退出，关闭也有限等待。无法确认隔离时停止总采集，禁止继续可能被污染的样本；整轮超时仍不单独证明界面无响应。

每个模型和显示模式三次独立 Electron 临时配置启动，1440×900、深色主题、正常自动快照与过程功能开启。正式测量包含生产 IPC 与真实核心；建模成本为共享领域 API 构造全模型的耗时，不冒充逐节点人工 UI 操作成本。选取通过项目树的真实选择入口，旋转通过实际画布拖拽。默认实体先核实为启用；分析线另开完整同规模轮次，不隐藏结构。

取消在观察到原生真实组装阶段后点击正式按钮。时间从实际点击到 DOM 取消确认和子进程 close 的较晚者，另存自动化往返耗时；随后等待迟到输出窗口并保存，检查模型不变、结果数不增加。低内存故障使用 16 MiB Windows Job 收紧预算，保留故障输入、诊断及已有历史结果，核实随后仍能旋转和保存。

内存口径分开：原生进程 Windows Job peak committed bytes 是提交内存峰值；Electron 每 100 ms 采样各进程工作集的总和，报告最大观测值。后者可能重复计共享页且漏掉短暂峰值，是采样下界，不能叫精确瞬时全应用峰值。原生不在 Electron app metrics 内，单独报告，不混算节省率，不强制 GC 改善结果。

试运行发现详细 JSON 过程复制引起原生预算耗尽。静力恢复数组、工程映射、细分历史、终态封装改为移动所有权，并在超预算网格构造前检查方程规模；保留完整 17 站响应、实际组装贡献、冻结输入及全部真实运行。数值／求解算法、参考和门槛不变。受控失败也输出独立 stderr 资源遥测，预算拒绝说明所需／可用方程数。操作系统终止或进程崩溃可能没有遥测，正式报告把缺失计为失败。试运行的默认每杆最多八单元候选超过已知可用方程预算，正式协议在登记前明确只生成 1／2 候选；历史失败仍保留，不把这些试运行作为正式通过证据。

随机原生分支与其他方法使用相同的退出码、传输错误、完整解码及资源遥测检查。桌面随机显示／导出尚无目标规模依赖时明确未测量，最终总判定要求该覆盖存在，禁止将单次成功包当完整验收。T2-43 真人试用与 T2-44 干净安装不属于本测量。
