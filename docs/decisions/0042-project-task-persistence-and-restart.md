# ADR-0042：项目任务保存、旧格式迁移与重启续作

- 日期：2026-10-05（Asia/Taipei）
- 状态：已接受
- 范围：PLAN2.0.md T2-09；US2-026—030、033、085；AC2-04、10、11、23 的正式保存／重开部分

## 决定

项目格式升级为 v2，继续读取 v1。迁移保留稳定对象身份、材料截面、工况荷载及历史冻结输入，登记缺少任务状态、确认回执及截面几何，不生成这些工程数据。未来项目版本、未来任务状态版本、跨项目或损坏恢复数据在激活项目之前拒绝。打开与迁移只读原文件，用户明确保存后才写入 v2；保存继续使用临时文件、备份与失败回滚。

正式项目携带版本化任务状态：目标、绑定对象、各类待确认草案及基础工程、参数来源、成功工具回执、调度描述、计算意图与来源、诊断工具证据和冻结计算输入。基础工程移除任务和回执以避免递归嵌套。项目摘要移除助手正文、完整请求正文、渐进输出和时间线事件；继续任务所需的目标与工具事实保留。

全部对话轮次保存在 `userData/chat-history/<projectId>.json`，按项目与轮次身份关联工程摘要。只允许安全项目身份生成本机路径，IPC 校验可信主窗口，单项目聊天写入按顺序使用原子文件存储。密钥字段、常见密钥文本与 Bearer 凭据在工程和聊天写入前去除；连接凭据继续由独立安全存储管理。本机正文读取失败或写入失败显示错误，仍允许正式项目保存和离线工作。本机正文只能补正文；工程文件中不存在的旧任务仅供查看，不能恢复其草案或执行意图。

重开不恢复网络请求或可执行调度闭包。已保存的运行／暂停／失败／排队状态作为历史证据显示，用户选择任务后核对身份、目标、草案基础、来源及成功回执。兼容草案沿用 T2-05 三方协调，冲突保持暂停；未确认草案仍待确认。成功回执与应用后的工程内容同时保存。确认只比较工程输入，任务元数据写入不使确认失效。重复确认优先返回持久回执；撤销／重做保留回执账本，旧重试不会抵消撤销。工程改变或回执缺失时，不允许静默续算。

计算任务保存不可变输入，不保存数值算法内部状态。用户继续时核对当前输入与保存输入，从同一冻结输入重新启动本地求解。恢复过程不依赖网络或 AI 凭据。新启动任务重新读取当前工程，继续使用项目级调度与跨项目迟到响应隔离。

## 边界与替代方案

未采用聊天推断工程状态、恢复可执行闭包或把聊天全文嵌入工程文件：这些方式无法保证用户确认、工程来源和状态一致性。暂未引入自动恢复事务日志；未正式保存的工作、提交时进程崩溃及自动快照的一致性属于 T2-10。真实 AI 联测与干净 Windows 安装仍由 T2-11／T2-41、T2-44 验收。

本决定替换 ADR-0028、ADR-0036 中限于当前会话的恢复／聊天保存规则，并扩展 ADR-0039 的任务状态持久化；原取消、真实过程记录及资源调度原则继续适用。

证据：[T2-09 验收](../evidence/plan2/T2-09/acceptance.md)。
