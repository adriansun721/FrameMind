# ADR-0049：可复用荷载、分析工况与结果依赖

日期：2026-10-05（Asia/Taipei）。范围：PLAN2.0 T2-16。

## 定义与身份

保留 LC 荷载定义和 CB 用户线性组合；新增 AC 分析工况，记录稳定身份、名称、方法、荷载来源和数值设置。多个 AC 可引用同一 LC 或 CB。当前只接受 static 与已验证的 native-static 预设，不提供尚未验证的可调阈值。正式计算仍使用 native/2；参考 TypeScript 求解仅用于显式验证。

分析快照额外冻结 analysisCase；服务 sourceId 为 AC，dependencies 继续记录实际 LC 与系数。C++ 两条协议路径核验 AC 与冻结荷载来源、方法和设置，数值组装及恢复算法不变。旧 LC/CB 直接计算入口仍可用。

旧 v1/v2 文件缺少 analysisCases 时按已保存的 LC、CB 顺序生成 AC1…，以 legacySourceId 映射旧结果。迁移不改写历史 input 或 service。映射工况首次运行前可查看原结果，运行后优先选取其自身结果。原来源相同的迁移前后静力结果可以比较；独立创建的 AC 不因共用荷载而混为同一分析来源。字段采用现有格式 v2 的可选扩展，旧版本应用不具备新 AC 管理能力。

## 依赖与历史

有效性由数值依赖投影判断，独立于项目修订、当前浏览、选择和 AC 名称。投影包含模型节点、杆件、支座、实际引用的材料／截面属性、所属荷载和组合系数、理论、单位、DOF、实际求解配置及 AC 方法／来源／设置。未赋给杆件的资源不参与依赖；密度仅在有效自重源参与时纳入；未启用自重的重力参数和零系数工况的荷载修改不使结果过期。LC 名称／说明保留原有来源变化判定，以兼容既有工况行为。

冻结快照仍保存全部历史来源，投影不裁剪报告或过程输入。共享 LC 修改会使依赖它的所有 AC、CB 结果过期，无需维护第二套可变失效标记。后续下游分析须在快照记录其上游冻结身份并扩展同一投影。

删除定义级联清理其荷载、组合和 AC；保留所有完成结果与冻结输入，删除来源的结果过期。文件解码对历史引用使用其自身冻结条件校验，不再要求历史来源仍存在于当前项目。这替代 ADR-0011、0012、0016 中删除来源时清理历史的旧规则。正式模型中的悬空引用仍拒绝。

## 入口与能力矩阵

分析工况管理提供创建、编辑、选择、计算、删除、荷载／组合编辑和历史查看。UI 使用能力注册表展示当前支持矩阵：静力支持同一结构下的荷载输入组合和线性响应规律；生产组合重新求解加权输入，不直接相加历史结果。二阶、屈曲、模态、随机尚未开放，不能在 UI 或领域／Agent／原生入口调用。后续方法的输入组合、响应叠加和比较规则由对应任务补齐并验证，不能仅修改 available 开关。

Agent 用 read_model 的 analysis-cases 集合查询，使用已有 propose_model_edits 的 create/update/delete_analysis_case 操作准备草案；手动与确认执行相同领域操作。草案重启、幂等回执、任务源绑定、续算和历史引用沿用既有契约。结果面板、引用与计算书显示冻结的 AC 与荷载来源。

## 验证边界

公开领域／服务／Agent／文件入口验证复用、依赖、稳定身份、迁移、组合比较及保存失败。原生核验沿用 T2-14 登记参考，新增来源协议不改变数值方法；保存 JSON 的 -0 与 0 视为同一零。桌面回放调用真实 C++ 并验证保存重开与删除来源后的历史。真实 AI 新能力联测、干净 Windows 和后续分析方法仍由后续任务验收。
