# ADR-0033：T32 固定规模性能验收

登记日期：2026-10-02（Asia/Taipei）。首次测量前登记，基线提交 `663bea8830685b12f8e38a795cfab21321b91d8a`。

## 环境与输入

Windows 11 家庭版中文版 10.0.26200；Intel i7-14650HX，16 核 / 24 逻辑处理器；物理内存 16,873,545,728 bytes。使用本机生产 Vite/Electron 构建、隔离用户目录、1440 × 900 内容窗口，离线运行。脚本保存 Node/Electron/Chromium 版本、构建文件 SHA-256 和机器记录。测量时电源/其他进程采用本次实际状态，不承诺其他硬件表现。

固定三维规则刚架：S 为 3 × 4 轴线、2 层（58 杆、36 节点）；M 为 7 × 7 轴线、3 层（399 杆、196 节点）；L 为 10 × 10 轴线、4 层（1,120 杆、500 节点）。X/Y 跨长均 5 m，层高 3 m，地面节点六自由度全固定；E=200 GPa、ν=.3、ρ=7,850 kg/m³，A=.02 m²，Iy=.0002 m⁴，Iz=.0003 m⁴，J=.0001 m⁴，截面转角 0°。LC1 为自重及每层每个节点全局 Z=-10 kN，LC2 为顶层节点 X=2 kN、Y=1 kN；各水平梁在 LC1 施加全局 Z=-2 kN/m；CB1=1.2 LC1+1.4 LC2。材料和截面是固定测量假设，不是规范设计。

每个模型保留 LC1 与 CB1 的完整节点/杆端响应及整体过程，两次分析历史；双格式正文导出全部结果，附录选择首根杆件过程、自由度编号和约束向量。大矩阵沿用 72 阶上限；不能将未测全部杆件逐项附录声称通过。

## 预定标准与方法

每种规模进行 3 次独立桌面运行，全部单次均需通过，不以均值掩盖失败。记录原始时间、采样内存、响应间隔和文件大小，汇总中位数与最大值。文件打开测到项目树和三维首帧准备完成；旋转用实际鼠标拖动并验证相机变化，选取用项目树稳定身份并验证属性；批量修改 20 根杆件为 5°后撤销。求解经真实 Worker，求解过程中执行实际旋转；取消测从点击到可再次运行，不用假 Worker。过程查看覆盖整体自由度、首根成员贡献展开；结果切换覆盖变形与内力图及 LC1/CB1 来源。

| 指标 | 所有规模通过标准 |
| --- | --- |
| 打开已有两次结果的项目 | ≤5,000 ms |
| 旋转 / 选择对象 / 批量提交 / 结果切换 / 过程展开 | 每项 ≤1,000 ms |
| 旋转帧间隔 | p95 ≤100 ms，最大 ≤500 ms（仅实际拖动区间） |
| 求解（含快照、Worker 传输与结果提交） | S ≤10,000 ms；M ≤20,000 ms；L ≤30,000 ms |
| 取消反馈 | ≤500 ms；旧任务结果不得提交 |
| 求解期间主界面定时回调间隔 | 最大 ≤500 ms |
| Word / PDF 文件完成（含附录、实际本地写入） | 每种 ≤60,000 ms |
| 过程展开及导出期间主界面定时回调间隔 | 最大 ≤500 ms |
| Electron 全部进程工作集采样峰值 | ≤2 GiB（每 100 ms 采样；短于采样间隔的峰值不代表已捕获） |

耗时使用 monotonic clock，响应由 renderer 每 20 ms 定时回调及 requestAnimationFrame 观测。导出过程中保持主窗口可操作；如发现同步报告生成瓶颈，把报告内容构造/打包迁入 Worker，图像栅格化保持浏览器支持的路径。矩阵过程按页/按展开显示，用户仍可访问全部条目。求解优化保持单元理论、约束消元、部分主元与预定容差，使用 T31 独立基准确认数值行为。

## 约定的验证入口

遵循 PLAN 第 7 节：`solveFrame`/`captureAnalysisInput`、项目编码解码、工程计算书捕获和桌面公开操作为测试入口。新增性能回归围绕用户行为，不断言私有实现或内部调用顺序。无需联网 AI，也不把性能测量等同 T33 首次使用或 T34 安装验收。

阈值在首次测量前固定；修正只针对实测失败项，记录基线及复测。若仍失败，记录失败，不放宽阈值。

2026-10-03 测量方法修正：CPU 采样发现 Playwright 全页面 `getByRole` 在数千对象按钮上反复计算可访问名称，占用约 1.8 秒，并污染界面回调间隔。改用已确认 DOM 上的稳定 aria-label CSS 选择器与局部选择器，仍执行相同点击、拖动和公开状态断言。阈值、模型、操作和重复次数均不变。此前迭代保留并标记存在自动化干扰；它们不能用于宣称用户交互耗时。

审查后的方法修正：旋转帧间隔由 canvas 实际 pointerdown 到 document pointerup 标记，只收集拖动期间的 rAF；打开项目除检查树条目外，再检查三维成员数量，并等待两帧。修正扩大了公开状态核对，未更改模型或通过阈值。

## 实现选择

项目树和结果按 50 条分页，整体过程按页及展开构建；节点自由度每页 100 条，组装贡献每页 25 条。条目数量、稳定身份和完整数据保留。大模型的分析线/节点及结果曲线按材质合并绘制，命中代理保留；超过 100 个条件时仅标注选中对象，完整编号可在项目树访问。荷载方向 glyph 仍显示，界面明确提示标注策略。

位移/内力采样使用已记录杆端力和均布荷载积分，避免每个站点重建刚度矩阵；单元理论、密集矩阵求解、部分主元及容差不变。脏状态比较使用保存时的不可变项目检查点，结果有效性和图形采样按输入/结果缓存，项目 JSON 紧凑编码且兼容原格式。

报告冻结选中分析及模型，再在独立 Worker 验证来源、构建正文和打包。Word 大模型表格直接序列化为可编辑 OOXML，使用内容碰撞检查的唯一占位符，保留字体、重复表头和不可拆行设置。`jszip` 从开发依赖移至产品依赖。PDF 使用离线临时 HTML，避免超长 data URL；按表格行数和单批单元格数量顺序使用隐藏 Chromium 窗口排版，以新增 `pdf-lib` 合并页面并写全局页码。[copyPages 官方 API](https://pdf-lib.js.org/docs/api/classes/pdfdocument#copypages) 保留复制页上的嵌入资源。替代方案为单次整份排版，但实测内存超标；分批增加排版耗时，换取峰值内存下降。所有窗口、Worker 和临时目录沿既有成功/失败边界释放，产品导出不依赖 Word、Python 或网络。

过程/导出测试沿公开输入输出验证完整末行、矩阵按需可访问、冻结来源和用户文本占位符碰撞。数值另复跑 T31 独立参考；最终数据和限制见 [T32 验收记录](../evidence/T32-validation.md)。
