# ADR-0043：一致的自动恢复快照

- 日期：2026-10-05（Asia/Taipei）
- 状态：已接受
- 范围：PLAN2.0.md T2-10；US2-027、031、032；AC2-04、10、23 的自动恢复部分

## 决定

在本机 `userData/recovery` 保存独立快照，不调用正式项目保存，不改变正式文件或已保存标记。快照携带完整 v2 工程（模型、冻结分析输入、关键任务状态、确认回执账本），以及项目身份、生成时间和最近一次正式保存的路径／时间。完整聊天和凭据继续使用 ADR-0042 的独立本机存储。项目与快照写入前脱敏，不把连接设置放入工程。

工程或任务状态变化后，在第一笔变更的 250 ms 后捕获当前完整工程；连续变化不重置该时间窗口。另设 2 秒检查，用于故障重试和兜底。内容与正式来源相同则不重复写入。切换项目前提交当前工程快照。每项目独立保留最近捕获请求，已切出的项目写入失败也继续重试；其他项目成功不会清除尚未解决的失败提示，同项目旧捕获的完成不覆盖新捕获状态。尚无节点、修改或任务的空白初始工程不产生恢复项。自动恢复允许找回未正式保存的新项目，也保留正常关闭时未保存的工作；不是仅凭进程异常标志判断是否显示。

确认操作仍是同步纯工程事务：只有模型与持久回执均已组装完成的对象才发布到工作台。自动快照不保存事务内部中间对象，整个工程、任务和回执写入同一 JSON。提交前中断恢复此前完整状态；提交后中断要么恢复此前状态，要么恢复含已应用模型与回执的完整新状态。草案状态即使在确认后尚未刷新，重复确认也先返回项目账本中的幂等回执，不重建对象。撤销继续保留回执账本，不被旧重试抵消。

快照采用不可变代际文件：写新临时文件、同步内容、关闭文件，再在同目录原子改名。SHA-256 校验整个快照载荷及来源元数据，生成编号结合已有文件与时钟保持重启后的排序。每项目保留最近三份校验完整的代际，只在新代际提交成功后清理更旧代际。中途留下的 `.tmp` 不作为恢复候选；损坏的正式快照保留供核查并显示跳过提示。磁盘写入失败保留旧代际，界面提示手动保存并持续重试，离线编辑与求解仍可用。

启动先检查恢复目录，不挂载工作台、Agent 或分析入口。按项目选取最新可读取且通过 v2 工程解码的代际；损坏或不兼容代际回退到更早完整代际。若最新有效快照与其正式文件内容相同，不重复显示恢复项；结构化比较忽略 JSON 对象键的排列，数组顺序与实际字段仍参与比较。候选显示项目身份、快照时间／本机自动来源、正式保存路径／时间或“尚未手动保存”。用户明确选择恢复或暂不恢复后进入工作台；目录读取失败可重试或进入工作台打开正式项目。

恢复后的工程保持未保存标记，并持续显示自动快照来源，直到用户正式保存。恢复不启动 AI、计算、深度探索或确认变更。任务摘要、未确认草案、暂停／失败／队列状态与冻结输入保留，使用 T2-09 的“恢复任务／继续任务／继续本地计算”显式核对入口。

## 边界与替代方案

未使用单一覆盖式自动保存文件或分别写模型与回执的存储，因为进程终止时可能留下缺文件或跨版本状态。也未引入逐操作磁盘事务日志：当前同步确认没有异步外部修改，完整代际快照可以保证已捕获状态的一致性，同时保持正式保存含义。

自动快照不承诺保留最后一次尚未捕获的内存变更；250 ms 捕获窗口以及磁盘故障期间仍可能失去新工作。验证覆盖 Windows 进程终止和文件系统故障，不据此承诺硬件掉电、文件系统损坏后的全部数据持久性。跨项目不设置总项目数淘汰，以免静默丢弃其他未保存项目；每项目三个完整代际之外的损坏／临时代际当前保留。
