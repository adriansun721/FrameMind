# ADR-0045：统一分析服务的静力兼容边界

- 日期：2026-10-05（Asia/Taipei）
- 状态：Accepted
- 范围：PLAN2.0 T2-12；延续 ADR-0006、0019、0032、0039、0040

## 决定与边界

采用 `framemind-analysis/1` 的可 JSON 序列化 DTO。`createAnalysisRequest` 在异步派发前复制并冻结输入，分配请求与分析身份，记录正式模型、诊断副本或历史补算来源及工况依赖。`executeAnalysisRequest` 是现有 TypeScript 求解器的适配入口；不改变刚度、荷载或求解算法。桌面手动计算、agent 续算、过程及报告补算保留 `startAnalysisTask` API，由独立模块 Worker 执行服务请求。诊断工具的独立 Worker 调用同一个服务适配入口；诊断副本不写入正式结果集合。

选择 DTO 而非把渲染器状态或库矩阵对象作为接口，便于 T2-13 在 Windows 本地桥接时核对同一输入输出；本任务不选择 C++ 数值库、二进制消息框架或新原生依赖，也不宣称已运行 C++。库、版本、许可、子进程／其他运行边界、安装证明及最终桥接传输由 T2-13 验证，正式入口切换与故障隔离由 T2-15 完成。现有 `solveFrame` 公共入口仍可用；禁止以后用静默回退把 TypeScript 输出标作 C++。

服务只接受当前已验证的理论、单位、自由度和完整数值配置。原求解器以固定 `1e-12` 相对主元阈值运行，服务拒绝其他阈值，避免保存一个实际未使用的设置。旧冻结输入缺少 solver 时，明确选择当前 TypeScript 配置。输出对输入、请求、来源、版本、有限数及完整对象集合校验；协议／Worker 错误同样返回 `AnalysisFailure`，保留阶段、诊断代码、字段和运行身份。

畸形协议包没有可读取的工程身份时，错误仍有真实模型检查阶段和 `input` 字段诊断；无法构造的运行来源明确缺失，不编造项目身份。Worker 失败载荷校验阶段枚举、诊断数组及定位字段，成功记录的阶段列表必须与实际接收的阶段消息一致。

## 坐标、单位、符号与映射契约

| 项 | v1 约定 |
| --- | --- |
| 全局坐标与转动 | 右手 XYZ；平移正向沿各轴，转角／力矩按右手法则 |
| 节点顺序 | 按冻结 `nodes` 数组顺序；每节点 `ux, uy, uz, rx, ry, rz`；整体索引从 0 起 |
| 单元顺序 | 起点六自由度，然后终点六自由度；映射用稳定节点／杆件 ID，不能按 UI 选择或标签查找 |
| 局部轴 | x 为起点到终点；若 `abs(x·globalZ)<0.9`，取全局 Z 作参考，否则取 Y；y=normalize(reference×x)，z=x×y；截面转角绕局部正 x |
| 转换 | 局部轴作为 T 的行；`u_local=T*u_global`，`K_global=Tᵀ*K_local*T` |
| 内部量纲 | 长度／位移 m；转角 rad；力 kN；力矩 kN·m；线荷载 kN/m；E 输入 GPa（乘 10⁶ 成 kN/m²）；密度 kg/m³；重力 m/s²；A m²；Iy/Iz/J m⁴ |
| 外荷载／反力 | 节点力与力矩沿全局正轴；均布力保留 global/local 标识；反力为 `K*u-F`；受约束位移为零 |
| 杆端分量 | `N,Vy,Vz,T,My,Mz`，两端均沿局部轴；为 `K_local*u_local-F_equivalent` 的端部作用量，不能直接当作截面包络 |
| 沿杆截面 | 位置 x 从工程杆起点计，以 m 表示；正局部 x 面上的截面作用量；按现有 `getMemberSectionForces` 恢复并以独立参考核对 |
| 工况组合 | 保存原始分项、系数及加权有效荷载；依赖保留负系数与零系数，不再次加权有效荷载 |

[wire-samples.json](../evidence/plan2/T2-12/wire-samples.json) 保存六种独立端荷载、六分量共同作用、竖直及斜向转角杆的完整请求和实际返回。样本是 TypeScript 兼容基准，不能代替 T2-13 的原生独立数值验证。

## 真实阶段、过程与取消

仅在求解器实际进入模型检查、刚度组装、方程求解、结果恢复时记录阶段和 ISO 开始时间。没有百分比、估算耗时或编造的阶段；服务契约拒绝发生在调用求解器前，运行阶段列表为空，诊断阶段为模型检查。失败与取消只保存已经观察到的阶段，不创建成功结果。Worker 取消终止该 Worker；无 Worker 或构造失败的受限运行时保持现有异步回退，其同步求解过程中无法处理另一个事件循环的取消，但取消后的输出不能提交。

运行记录随结果持久化，agent 查询、过程面板及 Word/PDF 共用它。历史结果没有服务记录时明确显示未保存原始阶段；不从当前模型重建阶段。补算分配新身份并引用旧分析 ID，不修改正文来源。整体过程快照保持现有 72 自由度完整矩阵上限及每杆 12×12 组装贡献；成员过程重建仍明确标注重建。

后续原生核心必须提供实际 DOF 映射、单元组装贡献、等效荷载、荷载向量、自由／约束集合、可用的实际矩阵、结果恢复量和求解版本。未返回的记录应明确缺失，不能从 TypeScript 重算后标为原生实际过程。大数据分页／附录体积策略由 T2-36—T2-38 扩展。

## 验证

继续使用 ADR-0032 预登记的独立参考及量纲容差，基准程序允许传入公开求解入口，因此服务和旧直接入口使用同一检查器。T2-12 全部 22 个成功算例、7 个失败算例及 2,322 项分量／平衡／过程检查通过；没有修改参考或放宽容差。确定性测试覆盖冻结时机、取消与迟到输出、求解及传输错误、来源、保存重开、历史过期和报告同源。Electron 用真实 Worker 从公开手动入口计算、浏览、保存、重开并导出报告；既有 agent 确认续算和隔离试算回放验证共用通路。真实 AI 新能力联测、原生核心、目标规模、干净 Windows 安装仍属后续任务。
