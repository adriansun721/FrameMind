# ADR-0077：STEP 整体确认、恢复与项目 checkpoint 边界

- 日期：2026-10-10（Asia/Taipei）
- 状态：本地实现已接受；指定 STEP 和依赖任务最终验收待完成
- 范围：P25-06，及其所需的 P25-07 checkpoint 接口

## 决策

1. 导入替换项目全部工程输入，保留项目身份与历史分析证据。确认界面明确列出被替换的节点、杆件、支座和荷载；不自动推断支座、外荷载或自重。新对象使用项目已有编号计数器，避免旧结果中的对象身份被新对象冒用。整组应用只产生一次工程修订。
2. 父快照和草稿分别使用规范化 SHA-256。规范化对象键排序、忽略 undefined；数组顺序保留。父快照取现有 `.framemind` 编码并排除待修复草稿字段。草稿包含完整中间态身份、位姿、接触决定、资源修改历史和 AI 证据。确认前和应用前都重新运行确定性资源与拓扑检查，重新验证 AI 结构化 findings，而非相信 accepted 字符串。
3. 原 STEP 路径只保留在 main 进程的当前解析会话。提交前重新读取并核对字节哈希，限 256 MiB、10 秒；变化、丢失、外部窗口身份或旧会话均阻止应用。重开的草稿清除 AI 回执并标为恢复态，需要重新导入原文件；来源、几何和父快照一致时可重用已保存位姿和资源记录。
4. 新工程模型在内存中完整构建，经现有项目编码/解码回读验证后才提交。Git 在发布引用前回读候选项目与完整草稿并核对字节和 SHA-256；发布后直接切换已核验模型，不再执行独立回读 RPC。提交期间阻止模型编辑和文件快捷键。失败保留原工程模型与可复核草稿。
5. 项目历史使用 `%APPDATA%/framemind/project-history/<project-id>` 下独立 bare Git 仓库，属于应用管理的本地旁车。所有命令显式指定仓库，无 shell、源码仓库发现或远程操作。首次使用选用本机 Git；本机验证版本为 `2.53.0.windows.1`。无 Git 时不报告导入成功，手动编辑、项目保存和本地求解不依赖此入口。
6. checkpoint 包含现有项目 JSON、元数据、内容 SHA-256、工程修订、导入任务与输入哈希。确认提交另存规范化 `cad-draft.json`，包含完整中间态、资源修改与原始 AI 核验响应，其字节 SHA-256 等于项目回执的草稿哈希。证据可核验读取及导出，不是项目打开的依赖。导入前后两次 commit-tree 产物通过一次 CAS update-ref 整体公开；中途失败只留下不可达对象，主历史不出现半组成功。撤销/重做和用户明确恢复 checkpoint 都先写历史，再切换模型。恢复前展示当前项目到目标快照的对象增删、字段值与项目设置差异，查看差异所绑定的项目变化后预览失效。恢复清除旧会话和确认，不自动恢复执行在途任务。
7. 正式项目嵌入原文件名、导入时间、大小、单位、产品/实体计数、解析器与 CAD 版本、解析参数、位姿/接触/警告确认决定与确认时间，以及实例/来源实体到工程分段的一对多映射、截面/材料证据、刚接假设、导入哈希和确认回执。原 STEP 字节不嵌入项目。待修复草稿可另存于同一 `.framemind` 格式，正式工程对象不应用。读取时验证新增字段的结构及直接进入预览的叶字段，包括坐标系、单位因子、材料名称、手工截面形状与尺寸；原 STEP 或本机历史缺失不妨碍正式项目打开，界面明确无法重新核验的范围。缺少支座/荷载的提示在保存重开后持续显示，提示消失不代表刚度可解或规范验算通过。

## 未完成的依赖

此实现没有将 P25-07 整体标为完成：另存为历史复制、新历史选项、项目文件与引用索引的跨文件故障协议、随安装包交付 Git 运行库仍由 P25-07/P25-16 完成。目前本机旁车按项目身份管理，不随 `.framemind` 文件移动；移动到其他机器或删除历史时界面报告追溯限制。

指定《完整钢架装配.STEP》仍存在上游中心线/独立 CAD 基准阻塞，因此不能生成已确认工程模型。解析棱柱的成功应用使用明确标记的 AI transport 回放，只验证事务、持久化和恢复，不作为真实在线 AI 验收。
